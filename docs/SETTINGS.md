# 设置页（3.4.0）

## 1. 入口与定位

首页标题行右上角新增齿轮入口（`SettingsActivity`），放在 6 连击完整功能手势区域之外，
不改变隐藏手势的触发方式。设置页只放**跨设备的维护、诊断、关于**内容；
补发授权码、清除设备授权、修复包执行、文件/终端上下文操作仍留在各自页面。

## 2. 已迁入设置页的内容

| 分组 | 操作 | 说明 |
| --- | --- | --- |
| 终端 | 终端字号 | 跟随系统/小/中/大，写入 `TerminalSettingsStore`，终端页打开时生效 |
| 终端 | 清空命令历史 | 清空 `TerminalHistoryStore` 的最近 50 条命令，不影响设备 |
| 数据与缓存 | 清空全部设备记录 | 删除最近设备、别名、地址及保存的密码（二次确认） |
| 数据与缓存 | 清除全部已保存密码 | 保留设备/别名，只清掉 Keystore 密文（二次确认） |
| 数据与缓存 | 清理修复包缓存 | 删除最近解压的 `repair_packages/pkg_*` 与导入临时 ZIP，不影响 `.clpkg` 文件 |
| 数据与缓存 | 授权记录：查看/导出/清空 | 列表默认脱敏；导出前提示 JSON 含完整授权码；清空不影响设备授权 |
| 诊断 | 连接诊断日志：查看/复制/分享/清空 | 复用内存 `Diagnostics`，不落盘 |
| 诊断 | 检测授权服务 | 调用 `AuthClient.checkReachable()`，显示结果与时间 |
| 关于 | 版本 / 构建时间 / 版权 | 首页页脚保留同一份信息 |
| 关于 | 修复包签名公钥 / 容器版本 | 显示公钥指纹（当前 `b4f58297`）与 `.clpkg` v2 |
| 关于 | 复制版本信息 | 复制版本、构建时间、签名公钥，便于现场反馈 |
| 关于 | 隐私说明 | 说明 Keystore、授权码导出、终端历史、官方签名与清理不可恢复 |

## 3. 有意不迁入的内容

- **完整功能开关**：继续使用标题 6 连击 + 密码，不在设置页暴露“开启完整功能”入口。
- **补发授权码 / 清除授权码**：设备相关、带重启风险，留在设备页/授权页。
- **修复包执行/重试**：强上下文，留在修复包页。
- **网络诊断**：连接失败时就在首页使用，不从首页移走。
- **应用锁/FLAG_SECURE**：尚未实现，后续作为设置页的安全分组接入。

## 4. 交互与安全

- 齿轮用 `Widget.CasdonLink.Button.IconImage`，48dp 触控区，contentDescription “设置”。
- 破坏性操作全部二次确认；设置页不展示完整授权码，导出前明确敏感文件提示。
- 设置页可旋转重建，计数在 `onResume` 刷新；长流程仍由各业务页处理。
- 次要按钮补了 `backgroundTint=@null`，避免 Material 默认着色把启用状态的次按钮渲染成主色实心。

## 5. 验证

- 真机验证：齿轮入口、设置页滚动、字号切换并恢复、授权记录脱敏列表、授权服务检测、
  清空授权记录二次确认（取消执行）、6 连击手势仍能打开完整功能密码弹窗。
- 构建与单元测试通过；设置页本身为 UI 逻辑，未新增独立单元测试。
