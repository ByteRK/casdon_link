## 2. 测试中发现并修复（3.1.1）

### 2.1 二进制文件预览显示乱码，Q-01 的下载兜底分支不可达

- 现象：二进制文件（如可执行文件）被按 UTF-8 强行解码，界面显示乱码；`readText` 的命令以 `tr` 结尾，`head` 失败也会被当作成功，导致“无法作为文本打开”的兜底分支几乎不会命中。
- 修复：`FileRepository.readText` 解码后检查前 4096 字节是否含 NUL，命中即抛“无法作为文本打开”，由文件页展示“下载”兜底；新增 `FileTextTests` 5 个单元测试（NUL、中文、ANSI 控制序列、空内容、嗅探窗口外 NUL）。
- 验证：`/tmp/casdon_bin.dat`（18 B，含 NUL）预览提示无法打开 → 下载 → 缓存文件 18 B 与设备端逐字节一致。
